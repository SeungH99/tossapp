# 그때. 요즘 출시 후 콘텐츠 확장 로드맵

- 상태: 출시 후 작업용 기준 문서
- 기준일: 2026-08-05
- 현재 출시 기준: `src/content/manifest.json`의 `releaseContract`
- 관련 설계: `docs/superpowers/specs/2026-08-04-geuttae-yojeum-180-day-content-design.md`

## 1. 현재 동결 범위

최초 출시는 검수 완료된 콘텐츠만 포함한다.

| 구분 | 팩 | 세트 | 문제 |
| --- | ---: | ---: | ---: |
| 기본 퀴즈 | 6 | 180일 | 540 |
| 추억·대중문화 | 4 | 120세트 | 360 |
| 합계 | 10 | 300세트 | 900 |

현재 앱은 매니페스트에 존재하는 보너스 주제만 노출하므로 최초 출시에서는 `nostalgia`만 보인다. 아래 확장 작업은 최초 출시를 막지 않는다.

## 2. 장기 목표

기본 퀴즈 540문제를 유지하면서 보너스 여섯 주제를 각각 180세트, 540문제로 확장한다.

| 주제 ID | 사용자 표시명 | 최종 팩 | 최종 세트 | 최종 문제 |
| --- | --- | ---: | ---: | ---: |
| `nostalgia` | 추억·대중문화 | 6 | 180 | 540 |
| `korean-life` | 한국 생활사 | 6 | 180 | 540 |
| `language` | 말·속담·맞춤법 | 6 | 180 | 540 |
| `digital` | 디지털 생활 | 6 | 180 | 540 |
| `safety` | 안전 | 6 | 180 | 540 |
| `nature-general` | 자연·일반상식 | 6 | 180 | 540 |

장기 완성 재고는 기본 6팩과 보너스 36팩, 총 42팩·3,780문제다.

## 3. 권장 확장 순서

### 0단계: 출시 안정화와 데이터 확인

최초 출시 후 최소 2주 동안 오류, 콘텐츠 신고, 핵심 퀴즈 완료율, 보너스 진입·완료율, D1/D7 재방문을 확인한다. 다음 콘텐츠 제작은 병행할 수 있지만 새 주제 공개는 심각한 저장·광고·복원 오류가 없는 상태에서 진행한다.

확장 판단에 사용할 초기 내부 기준은 다음과 같다. 앱인토스 전체 평균을 의미하지 않는다.

- 첫 핵심 퀴즈 완료율 60% 이상
- D7 재방문 10% 이상
- 보너스 선택 후 세 문제 완료율이 지속적으로 하락하지 않음
- 문제 오류·정답 이의 제기에 대한 수정 절차가 정상 동작함

### 1단계: 추억·대중문화 180일 완성

`nostalgia`의 `pack-005`, `pack-006`을 추가해 60세트·180문제를 보강한다. 이미 노출 중인 주제를 완성하는 작업이므로 UI 변경이 적고 가장 먼저 진행한다.

완료 후 누적 재고: 12팩·1,080문제.

### 2단계: 한국 생활사

서비스 이름인 “그때. 요즘”과 가장 직접적으로 연결되는 신규 주제다. 과거 생활 방식과 현재 생활의 차이를 중심으로 구성하되, 특정 세대를 시험하거나 조롱하는 표현은 사용하지 않는다.

### 3단계: 말·속담·맞춤법

시간에 따른 사실 변경 위험이 낮고 정답 근거를 확인하기 쉬운 주제다. 지나치게 쉬운 관용 표현보다 헷갈리지만 풀고 나면 기억에 남는 문제를 우선한다.

### 4단계: 디지털 생활

스마트폰, 메신저, 보안, 온라인 행정처럼 실제 생활에 도움이 되는 문제를 제공한다. 서비스 화면과 제도는 바뀔 수 있으므로 모든 시의성 문제에 `validThrough`를 두고 만료 전 재검수한다.

### 5단계: 안전

교통·재난·생활 안전을 다룬다. 유용성은 높지만 잘못된 정보의 피해가 크므로 정부·공공기관 1차 출처 확인과 별도 고위험 검수를 통과한 문제만 공개한다.

### 6단계: 자연·일반상식

다른 주제로 분류되지 않는 검증 가능한 상식을 보완한다. 범위가 넓어 차별성이 약해질 수 있으므로 출시 데이터에서 실제 수요가 확인된 세부 영역부터 제작한다.

새 주제의 순서는 사용자 선택 데이터와 콘텐츠 신고율에 따라 바꿀 수 있다. 다만 한 번에 여러 주제를 동시에 공개하지 않고 한 주제씩 품질과 리텐션 영향을 확인한다.

## 4. 주제별 제작 단위

- 한 팩은 30세트·90문제다.
- 한 세트는 `gentle`, `steady`, `stretch` 문제를 정확히 한 개씩 포함한다.
- 신규 주제는 먼저 4팩·120세트·360문제를 완성하고 전체 검증 후 공개한다.
- 공개 후 남은 2팩·60세트·180문제를 추가해 180세트를 완성한다.
- 문제 수를 맞추기 위해 너무 쉬운 문제, 보기만 읽어도 답이 드러나는 문제, 표현만 바꾼 중복 문제를 넣지 않는다.

## 5. 첫 확장 전에 해결할 기술 작업

### 매니페스트 기준 세트 상한

보너스 주제의 실제 `setCount`를 `manifest.releaseContract`에서 읽어야 한다. 현재처럼 도메인 상한을 180으로 고정하면 120세트만 공개된 주제에서 존재하지 않는 121번째 세트를 요청할 수 있다.

- 카탈로그가 주제별 공개 세트 수를 제공한다.
- 다음 `setIndex`가 공개 세트 수 이상이면 팩 로드를 시도하지 않는다.
- 광고나 무료 보너스권을 소비하기 전에 `새 문제를 준비하고 있어요` 상태를 반환한다.
- 새 팩이 배포되면 기존 사용자는 다음 미완료 세트부터 자연스럽게 이어간다.

### 동적 주제 메타데이터

주제 표시명과 공개 순서를 앱 코드의 고정 배열이 아니라 매니페스트 또는 별도 주제 메타데이터에서 읽도록 정리한다. 공개되지 않은 주제는 UI, 접근성 트리, 분석 이벤트에 나타나지 않아야 한다.

### 콘텐츠 버전과 진행도 보존

- 팩 추가 시 `contentVersion`, descriptor, SHA-256, `releaseContract`를 같은 변경에서 갱신한다.
- 기존 문제 ID를 바꾸지 않는다.
- 교체가 필요한 문제는 `legacy-map.json` 감사 후 진행도 손실 여부를 확인한다.
- 진행 상태 V3, 미완료 세션, 광고 보상 명령의 멱등성을 유지한다.

## 6. 콘텐츠 품질 게이트

모든 신규 팩은 아래 조건을 만족해야 한다.

- 세트마다 문제 세 개와 난이도 세 단계가 정확히 대응함
- 정답이 보기 중 정확히 하나임
- 문제·정답·해설·출처가 서로 모순되지 않음
- 정부기관, 공공기관, 박물관, 사전 등 재검증 가능한 출처를 우선함
- 출처 없는 AI 생성 사실을 사용하지 않음
- 전체 라이브러리에서 문제·선택지·개념 중복과 과도한 유사도를 검사함
- 정답 위치와 난이도 분포가 한쪽으로 치우치지 않음
- 5060 사용자가 읽기 쉬운 문장 길이와 용어를 사용함
- `reviewStatus`가 `reviewed`이고 시의성 정보의 `validThrough`가 유효함

## 7. 구현 및 검증 절차

각 팩은 다음 순서로 추가한다.

1. `src/content/bonus/<topic>/pack-00X.json`에 30세트·90문제를 작성한다.
2. 팩 검증과 매니페스트 갱신을 실행한다.

   ```powershell
   npm.cmd run validate:content:pack -- src/content/bonus/<topic>/pack-00X.json --update-manifest
   ```

3. descriptor, SHA-256, 세트 범위, `releaseContract` 변경을 함께 검토한다.
4. 해당 주제 범위와 전체 라이브러리를 검증한다.

   ```powershell
   npm.cmd run validate:content:library -- --scope bonus:<topic>
   npm.cmd run validate:content
   ```

5. 진행도 복원, 일일 잠금, 소진 상태, 광고·이용권 보존 테스트를 추가한다.
6. 전체 출시 게이트를 실행한다.

   ```powershell
   npm.cmd run verify:release
   ```

7. 새 `.ait`의 deployment ID와 SHA-256을 기록한 뒤 토스 콘솔에 업로드한다.

## 8. 새 주제 공개 완료 기준

- 최소 4팩·120세트·360문제가 검수 완료됨
- 매니페스트에 해당 주제가 선언되고 앱에는 선언된 주제만 노출됨
- 주제 선택부터 세 문제 완료, 결과, 다음 날 다음 세트 열림까지 E2E 통과
- 콘텐츠 팩 로드 실패 시 같은 주제·세트로 재시도되고 광고·이용권이 보존됨
- 360px·390px, Chromium·WebKit에서 잘림과 차단 접근성 오류가 없음
- 전체 라이브러리가 수량, SHA-256, 중복, 난이도, 출처 검증을 통과함
- 메인 번들에 전체 문제를 넣지 않고 선택한 팩만 지연 로딩함
- 기존 사용자 진행도와 미완료 세션이 유지됨

## 9. 하지 않을 것

- 런타임 LLM으로 검수되지 않은 문제를 즉석 생성하지 않는다.
- 문제 수를 빠르게 늘리기 위해 정답이 자명한 상식을 채우지 않는다.
- 별도 근거 없이 난이도 선택 UI를 추가하지 않는다. 난이도는 내부 균형용으로 유지한다.
- 여러 주제를 동시에 공개해 어떤 주제가 리텐션에 기여했는지 알 수 없게 만들지 않는다.
- 정적 콘텐츠 확장과 광고 노출 빈도 확대를 같은 실험으로 묶지 않는다.

## 10. 다음 작업 시작점

확장을 재개할 때는 다음 순서로 시작한다.

1. 주제별 실제 세트 상한을 매니페스트에서 읽도록 수정한다.
2. `nostalgia` 121~150세트용 `pack-005`를 작성·검수한다.
3. `nostalgia` 151~180세트용 `pack-006`을 작성·검수한다.
4. 출시 데이터로 첫 신규 주제를 최종 선택한다.
5. 선택한 주제를 30세트 단위로 제작해 120세트에서 첫 공개한다.
