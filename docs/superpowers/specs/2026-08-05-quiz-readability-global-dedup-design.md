# 퀴즈 가독성 및 전역 중복 방지 설계

- 상태: 사용자 승인 설계
- 기준일: 2026-08-05
- 대상 앱: 그때. 요즘
- 승인 방향: 전역 개념 이력과 고정 보너스 세트

## 1. 목표

이번 변경은 다음 네 문제를 함께 해결한다.

1. 긴 문제의 글자가 지나치게 커서 읽기 어려운 문제
2. 한 줄 보기와 여러 줄 보기의 텍스트 시작 위치가 다른 문제
3. 정답 체크 아이콘이 긴 보기 때문에 찌그러지는 문제
4. 실제 출시 카탈로그에서 보너스 주제가 `추억·대중문화` 하나만 노출되는 문제

추가 요구사항으로, 사용자가 기본 퀴즈나 보너스에서 한 번 답한 문제와 같은 개념은 다시 출제하지 않는다. 문구만 바뀐 동일 개념도 중복으로 본다.

## 2. 확인된 원인

### 문제 제목

현재 문제 제목은 `clamp(27px, 7.4vw, 34px)`를 사용한다. 긴 문장에도 최소 27px이 적용돼 모바일 화면에서 줄 수가 급격히 늘어나고 문장 덩어리가 커진다.

### 보기 블록

보기 버튼은 `align-items: center`와 수직 패딩이 없는 `padding: 0 24px`를 사용한다. 따라서 한 줄 보기는 버튼 중앙에서 시작하고 여러 줄 보기는 더 위에서 시작한다. 선택 전 1px 테두리가 선택 후 2px로 바뀌는 것도 내부 시작선을 움직인다.

### 정답 아이콘

체크 아이콘 컨테이너에 축소 금지 규칙이 없다. 긴 보기 문장이 가로 공간을 차지하면 flex 레이아웃이 아이콘의 너비를 줄여 원을 타원으로 만든다.

### 보너스 주제

앱 코드에는 여섯 주제 이름이 있지만 `src/content/manifest.json`에는 `nostalgia` 팩만 등록돼 있다. 앱은 매니페스트에 등록된 주제만 노출하므로 사용자는 한 종류만 볼 수 있다.

## 3. 화면 설계

### 문제 제목 크기

문제 제목에 길이 상태를 명시한다.

- 41자 이하: `24px`에서 `28px` 사이의 반응형 크기
- 42자 이상: `21px`에서 `24px` 사이의 반응형 크기
- 긴 문제 행간: 약 `1.42`
- 자간은 현재보다 완화해 긴 한글 문장의 글자 뭉침을 줄인다.

문자 수 판정은 UTF-16 코드 유닛이 아니라 화면에 보이는 문자 수를 기준으로 한다. 제목 요소에는 `question-title`과 조건부 `long` 클래스를 사용한다.

### 보기 정렬

보기 버튼은 두 열 그리드로 바꾼다.

- 첫 열: 보기 텍스트
- 둘째 열: 선택된 경우에만 표시되는 정답 아이콘
- 모든 보기의 텍스트는 동일한 위쪽 패딩에서 시작
- 버튼 수직 패딩은 위아래 각각 18px
- 보기 텍스트 크기는 18px, 행간은 약 `1.45`
- 한 줄과 여러 줄 모두 왼쪽 정렬
- 선택 전후 테두리 두께는 2px로 고정해 레이아웃 이동을 없앰

### 정답 아이콘

문자 `✓` 대신 SVG 체크를 사용한다.

- 원형 컨테이너: 28×28px
- `min-width`, `min-height`, `aspect-ratio`, 축소 금지 적용
- SVG는 16×16px의 고정 `viewBox` 사용
- 장식 아이콘이므로 접근성 트리에서는 숨김

### 검증 화면 폭

360px과 390px에서 긴 문제, 한 줄 보기, 두 줄 보기, 선택 전후 상태를 스크린샷으로 검증한다. 200% 확대에서도 문제와 다음 버튼을 가리는 고정 요소가 없어야 한다.

## 4. 공개할 보너스 주제

이번 공개 대상은 다음 세 주제로 제한한다.

1. 추억·대중문화 (`nostalgia`)
2. 한국 생활사 (`korean-life`)
3. 말·속담·맞춤법 (`language`)

한국 생활사와 말·속담·맞춤법은 각각 최소 30세트, 90문제를 검수한 뒤 매니페스트에 등록한다. 세트마다 `gentle`, `steady`, `stretch` 문제를 한 개씩 포함한다. 검수된 팩이 없는 주제는 화면이나 접근성 트리에 노출하지 않는다.

디지털 생활, 안전, 자연·일반상식은 이번 범위에서 공개하지 않는다.

## 5. 전역 중복 방지 모델

### 전역 개념 ID

`conceptId`를 보너스 전용 필드에서 모든 문제의 필수 필드로 올린다. 같은 사실이나 풀이 개념을 묻는 문제는 문구와 문제 ID가 달라도 같은 `conceptId`를 사용한다.

출시 라이브러리에서는 동일한 `conceptId`의 재사용을 허용하지 않는다. 기존의 “30세트 이상 떨어진 변형 허용” 규칙은 이번 요구사항과 충돌하므로 제거한다.

### 사용자별 본 문제 이력

진행 상태를 버전 4로 올리고 다음 두 이력을 저장한다.

- `seenQuestionIds`: 사용자가 답한 문제 ID
- `seenConceptIds`: 사용자가 답한 문제의 전역 개념 ID

문제를 화면에 열었지만 아직 답하지 않은 활성 세션은 그대로 복원한다. 답을 제출한 시점부터 본 문제로 기록한다. 앱을 중간에 종료해도 이미 답한 문제는 다음 세션에서 다시 배정하지 않는다.

현재 저장소가 기기 내 영속 저장소이므로 이 보장은 동일한 앱 데이터 프로필 안에서 적용된다. 앱 삭제나 다른 기기까지 동기화하는 기능은 백엔드 계정 동기화가 필요한 별도 범위다.

### 진행 상태 마이그레이션

버전 1~3 상태를 버전 4로 올릴 때 다음 자료를 합친다.

- 완료된 기본·보너스 세션의 답변 문제 ID
- `answerEvents`에 남은 문제 ID와 `conceptId`
- `completedBonusIds`
- 레거시 문제와 새 문제의 명시적 매핑

개념을 확정할 수 없는 오래된 문제는 문제 ID만 본 것으로 기록한다. 근거 없이 다른 개념과 합치지 않는다.

## 6. 고정 세트 선택 규칙

고정 세트와 지연 로딩 구조는 유지한다. 보너스 시작 시 다음 순서로 처리한다.

1. 주제별 공개 세트 수를 매니페스트에서 읽는다.
2. 완료하거나 중복으로 건너뛴 세트를 제외하고 가장 앞의 세트를 찾는다.
3. 세 문제를 지연 로딩한다.
4. 세 문제의 `questionId`와 `conceptId`를 사용자 이력과 비교한다.
5. 하나라도 이미 본 항목이면 해당 세트를 `skippedSetIndexes`에 멱등하게 기록하고 다음 세트를 검사한다.
6. 중복 없는 세트를 찾은 뒤에만 무료 이용권, 연속 참여권 또는 광고 보상을 소비한다.
7. 공개 재고 끝까지 유효한 세트가 없으면 반복 출제 없이 `새 문제 준비 중` 상태를 반환한다.

활성 세션 복원은 예외다. 이미 시작한 동일 세션은 같은 세 문제를 이어서 보여준다. 이는 새 출제가 아니라 진행 복원이다.

## 7. 콘텐츠 검증

출시 검증은 기본과 세 보너스 주제를 하나의 라이브러리로 검사한다.

- 중복 문제 ID 금지
- 중복 `conceptId` 금지
- 완전히 같은 문제 문구 금지
- 기준치 이상의 유사 문구 금지
- 정답과 보기 중복 금지
- 세트별 난이도 세 단계 누락 금지
- 출처, 검수일, 콘텐츠 버전 누락 금지
- 매니페스트의 팩·세트·문제 수와 실제 파일 불일치 금지

자동 유사도 검사는 검수 보조 수단이다. 의미가 같지만 표현이 크게 다른 문제는 콘텐츠 리뷰에서 같은 `conceptId`로 분류한 뒤 한 문제만 출시한다.

## 8. 카탈로그 계약

`ContentCatalog`은 다음 정보를 제공한다.

- 공개 주제 목록과 표시 순서
- 주제별 공개 세트 수
- 주제와 세트 인덱스로 세 문제 로드

주제 표시명과 순서는 매니페스트의 공개 계약에서 읽는다. 앱 코드의 여섯 주제 고정 배열은 공개 여부의 기준으로 사용하지 않는다.

## 9. 오류 처리와 보상 보존

- 팩 로드 실패: 같은 주제와 세트로 재시도하며 보상을 소비하지 않음
- 중복 세트 발견: 건너뛰기 상태를 먼저 저장한 뒤 다음 세트를 검색
- 전체 재고 소진: 주제를 비활성화하고 `새 문제 준비 중` 표시
- 저장 실패: 현재 답변과 세션을 유지하고 재시도 제공
- 광고 완료 후 저장 실패: 멱등 명령 ID로 보상을 중복 지급하거나 잃지 않음

중복 때문에 세트를 건너뛴 경우 `bonus_set_skipped_seen_concept` 이벤트에 주제와 세트 인덱스만 기록한다. 개인 문제 이력이나 정답은 분석 이벤트에 보내지 않는다.

## 10. 테스트 전략

### 단위 테스트

- 긴 문제에 `long` 상태가 적용됨
- 한 줄과 두 줄 보기 모두 동일한 텍스트 래퍼 구조를 사용함
- 정답 표시는 SVG이며 고정 원형 컨테이너를 사용함
- 답 제출 시 문제 ID와 개념 ID가 즉시 본 이력에 추가됨
- 기본에서 본 개념을 포함한 보너스 세트를 건너뜀
- 다른 문제 ID지만 같은 `conceptId`인 문제를 건너뜀
- 건너뛴 세트가 다음 시작에서 다시 선택되지 않음
- 중복 검사 전에 광고권이나 이용권이 차감되지 않음
- 버전 1~3 상태가 버전 4로 손실 없이 마이그레이션됨

### 통합 및 E2E 테스트

- 세 주제만 선택 화면에 표시됨
- 각 주제에서 첫 미풀이 세트를 시작하고 완료할 수 있음
- 앱 재실행 후 완료 문제와 동일 개념이 다시 나오지 않음
- 재고 소진 주제는 비활성화됨
- 360px·390px Chromium과 WebKit 스크린샷에서 정렬과 아이콘이 유지됨
- 접근성 검사에서 버튼 이름, 진행 상태, 비활성 주제 안내가 유효함

## 11. 완료 기준

- 긴 문제의 글자 크기와 행간이 승인 규칙을 따름
- 모든 보기 텍스트의 시작선과 선택 전후 위치가 동일함
- 정답 아이콘이 어떤 보기 길이에서도 원형을 유지함
- 세 보너스 주제가 검수된 매니페스트를 통해 노출됨
- 사용자별 문제 ID와 개념 ID 중복 출제가 단위·E2E 테스트로 차단됨
- 재고 소진 시 반복 출제나 보상 차감이 없음
- 전체 품질, 콘텐츠, 빌드, Chromium·WebKit 출시 게이트가 통과함

## 12. 비범위

- 디지털 생활, 안전, 자연·일반상식 주제 공개
- 런타임 AI 문제 생성
- 사용자 난이도 선택 UI
- 앱 삭제 후 또는 여러 기기 간 문제 이력 동기화
- 광고 노출 빈도 변경
