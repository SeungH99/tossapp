# 그때. 요즘 180일 무반복 콘텐츠 설계

## 2026-08-05 MVP 출시 범위

- 최초 출시는 기본 180일 540문항과 추억 보너스 120세트 360문항만 포함한다.
- 총 출시 재고는 10팩·900문항이며 `src/content/manifest.json`의 `releaseContract`가 검증 기준의 단일 출처다.
- 나머지 추억 60세트와 생활·언어·디지털·안전·자연 보너스 주제는 출시 후 업데이트한다.
- 이후 문서의 42팩·3,780문항 설계는 장기 목표이며 MVP 출시 차단 조건이 아니다.

## 목표

5060 사용자가 매일 정답을 맞히는 즐거움과 새로 배우는 만족을 함께 느끼도록 콘텐츠 수준을 높인다. 보기만 읽어도 답이 드러나는 문제는 교체하고, 기본 퀴즈와 선택한 보너스 주제를 180일 동안 반복 없이 이용할 수 있는 정적 콘텐츠 라이브러리를 만든다.

이번 설계의 출시 계약은 다음과 같다.

- 기본 퀴즈: 180일 x 하루 3문제 = 540문제
- 보너스 퀴즈: 6주제 x 180세트 x 세트당 3문제 = 3,240문제
- 전체: 3,780문제
- 기본 세 영역은 `그때`, `요즘`, `생활`을 유지한다.
- 보너스는 주제별 하루 1세트로 제한한다.
- 같은 기기의 로컬 진행 데이터가 유지되는 동안 동일 문제를 다시 출제하지 않는다.
- 로그인, 백엔드, 교차 기기 동기화는 이번 범위에 포함하지 않는다.

## 사용자 경험

### 기본 퀴즈

- 매일 KST 기준으로 `그때`, `요즘`, `생활` 문제를 한 개씩 제공한다.
- 하루 세 문제에는 `gentle`, `steady`, `stretch`가 한 개씩 포함된다.
- 난이도 이름은 사용자에게 표시하지 않는다.
- 어느 영역이 쉬운지 고정하지 않고 날짜별로 난이도 배치를 순환한다.
- 출시 범위는 2026-07-28부터 2027-01-23까지 180일이다.
- 범위 밖 날짜나 콘텐츠 로드 실패 시 다른 날짜 문제를 대신 보여주지 않는다. 재시도 안내 또는 `새 문제를 준비하고 있어요` 상태를 표시한다.

### 보너스 퀴즈

- 기존 여섯 주제 선택을 유지한다: `추억·대중문화`, `한국 생활사`, `말·속담·맞춤법`, `디지털 생활`, `안전`, `자연·일반상식`.
- 각 주제는 180개의 고정 세트를 가지며 한 세트는 세 문제다.
- 사용자가 주제를 선택하면 그 주제의 다음 미완료 세트를 연다. 달력 날짜가 아니라 주제별 진행 순서를 사용하므로 늦게 시작해도 180세트를 모두 이용할 수 있다.
- 한 주제를 완료하면 그날은 해당 주제를 `오늘 완료`로 잠근다. 다른 주제는 계속 선택할 수 있어 하루 최대 6세트, 18문제까지 이용할 수 있다.
- 현재의 해제 우선순위인 `첫 무료 -> 무료 보너스권 -> 선택형 보상 광고`를 유지한다.
- 이미 완료한 주제를 다시 누르거나 소진된 주제를 누른 경우 광고나 이용권을 소비하지 않는다.
- 해당 주제의 180세트를 모두 완료하면 다른 주제 문제로 대체하지 않고 `새 문제를 준비하고 있어요`를 표시한다.
- 결과 화면, 공유 점수, 분석 이벤트에는 방금 완료한 세트의 실제 점수를 사용한다.

### 무반복 보장 범위

무반복은 로컬 `ProgressState`가 보존되는 한 같은 기기에서 보장한다. 앱 데이터 삭제, 기기 변경, 저장소 전체 손상 후 무저장 모드에서는 과거 진행을 복원할 수 없다. 교차 기기 보장을 위해 토스 로그인이나 별도 백엔드를 추가하지 않는다.

## 난이도 원칙

### 내부 난이도

| 난이도 | 사용자 경험 | 허용되는 문제 유형 | 금지되는 형태 |
|---|---|---|---|
| `gentle` | 기억을 더듬으면 풀 수 있음 | 익숙한 개념의 구분, 한 단계 회상 | 보기만 읽어도 답이 드러나는 문제 |
| `steady` | 비슷한 개념을 비교해야 함 | 원인과 결과, 용도 구분, 순서 판단 | 단어 뜻을 그대로 다시 묻는 문제 |
| `stretch` | 두 단계 사고가 필요함 | 상황 판단, 시대 비교, 조건 적용 | 전문지식이나 함정 표현에 의존하는 문제 |

기본 퀴즈는 매일 난이도별 한 문제를 포함한다. 각 보너스 주제의 매 세트도 난이도별 한 문제를 포함하므로 주제마다 `gentle` 180개, `steady` 180개, `stretch` 180개가 된다.

운영 목표는 성숙 코호트의 기본 퀴즈 평균 점수가 `1.8~2.2 / 3` 범위에 드는 것이다. 이 값은 빌드 검증 조건이 아니라 출시 후 공식 분석으로 판단하는 콘텐츠 조정 지표다.

### 품질 기준

다음 문항은 검수 완료 상태가 될 수 없다.

- 초등 저학년 수준의 단순 상식
- 질문 안에 정답 표현이 사실상 포함된 문항
- 정답 하나만 현저히 길거나 구체적인 보기
- 웃기거나 현실성이 없어 즉시 제거할 수 있는 오답
- 두 개 이상의 보기가 사실상 정답인 문항
- 출처가 정답과 해설을 직접 뒷받침하지 않는 문항
- 광고성, 정치 편향, 논쟁적 가치 판단에 의존하는 문항
- 가격, 현직 인물, 최신 뉴스처럼 빠르게 낡는 문항
- 질병 진단, 투자 판단 등 고위험 전문 조언으로 읽힐 수 있는 문항

오답은 실제로 혼동할 수 있는 같은 범주의 개념으로 만든다. 해설은 정답 근거와 함께 사용자가 헷갈릴 가능성이 큰 보기가 틀린 이유를 짧게 설명한다.

## 콘텐츠 저장 구조

### 디렉터리

```text
src/content/
├─ manifest.json
├─ core/
│  ├─ pack-001.json
│  ├─ ...
│  └─ pack-006.json
└─ bonus/
   ├─ nostalgia/pack-001.json ... pack-006.json
   ├─ korean-life/pack-001.json ... pack-006.json
   ├─ language/pack-001.json ... pack-006.json
   ├─ digital/pack-001.json ... pack-006.json
   ├─ safety/pack-001.json ... pack-006.json
   └─ nature-general/pack-001.json ... pack-006.json
```

- 기본 팩은 30일, 90문제 단위로 6개다.
- 보너스 팩은 주제별 30세트, 90문제 단위로 6개씩 총 36개다.
- 전체 콘텐츠 팩은 42개다.
- 앱은 현재 날짜의 기본 팩과 선택한 주제의 필요한 보너스 팩만 동적으로 불러온다.
- `manifest.json`은 콘텐츠 버전, 활성 기간, 팩 경로, 문제 수, 세트 수, 검수 상태와 체크섬을 기록한다.
- 빌드 시 모든 JSON을 실행 가능한 스키마로 파싱하며 런타임에서는 검증된 타입만 사용한다.

### 문제 스키마 변경

공통 필드에 다음 메타데이터를 추가한다.

```text
contentVersion
reviewStatus: draft | fact-checked | reviewed
reviewedAt
validThrough (시간에 민감한 사실에만 사용)
source.name
source.url
```

`CoreQuestion`에는 `internalDifficulty`를 추가한다. `BonusQuestion`에는 기존 `conceptId`, `variant`, `internalDifficulty`를 유지하고 `setIndex`를 추가한다. `setIndex`는 주제 안에서 `0..179`이며 같은 주제와 `setIndex`를 가진 문제는 정확히 세 개여야 한다.

## 선택과 진행 상태

### 보너스 선택 규칙

기존 `selectBonusQuestions()`의 다른 주제 폴백은 제거한다. 새 선택기는 다음 순서로 동작한다.

1. 완료되지 않은 보너스 세션이 있으면 새 주제를 열지 않고 해당 세션을 복원한다.
2. 선택한 주제가 오늘 이미 완료됐는지 확인한다.
3. 주제의 `completedSetIndexes`에 없는 가장 작은 `setIndex`를 찾는다.
4. 해당 주제와 `setIndex`에 속한 세 문제를 불러온다.
5. 세 문제와 콘텐츠 팩이 모두 검수 완료 상태인지 확인한다.
6. 보너스 해제 권리를 확정한 뒤 세션 시작을 원자적으로 저장한다.
7. 세 문제 완료 시에만 해당 `setIndex`를 `completedSetIndexes`에 추가하고 `lastCompletedDateKey`를 기록한다.

같은 명령이 재시도되면 기존 세션을 반환하고 완료 세트나 해제 권리를 두 번 기록하지 않는다. 콘텐츠 팩 로드 실패, 주제 일일 제한, 세트 소진은 해제 권리를 소비하기 전에 반환한다.

### 저장소 마이그레이션

`ProgressState`를 버전 3으로 올리고 다음 상태를 추가한다.

```text
bonusTopicProgress[topic].lastCompletedDateKey
bonusTopicProgress[topic].completedSetIndexes
```

`nextSetIndex`는 저장하지 않고 `0..179` 중 완료되지 않은 가장 작은 번호로 계산한다. 저장된 진행 번호와 완료 목록이 어긋나는 이중 진실 공급원을 만들지 않는다.

버전 1과 2의 `completedBonusIds`, `bonusStartCommands`, 저장된 세션은 보존한다. `legacy-map.json`은 유지되는 기존 문제 ID를 새 주제와 `setIndex`에 명시적으로 연결한다. 같은 기존 세션에서 완료된 세 문제 전부가 하나의 새 세트로 매핑될 때만 그 `setIndex`를 완료로 반영한다. 일부 문제만 매핑되거나 교체로 제거된 ID는 감사 기록에 남기되 새 세트를 완료로 간주하지 않는다. 진행 상태 revision과 단일 writer 규칙은 기존 저장소 계약을 유지한다.

## 제작과 검수 파이프라인

각 30일 팩은 다음 상태를 순서대로 거친다.

1. 구조화된 초안 작성
2. 출처를 통한 사실 검증
3. 질문, 보기, 해설의 편집 검수
4. 자동 스키마 및 품질 감사
5. `reviewed` 상태와 체크섬 생성
6. 전체 릴리스 계약 검증

정답 근거는 정부기관, 공공기관, 박물관, 표준국어대사전 등 재검증 가능한 출처를 우선한다. 출처 없는 AI 생성 사실은 허용하지 않는다. 시간에 민감한 정보는 `validThrough`가 180일 활성 범위를 포함할 때만 사용할 수 있다.

### 강제 실패 검증

- 기본 540문제, 보너스 3,240문제, 전체 3,780문제
- 기본 날짜 180개와 날짜별 세 영역 각 한 문제
- 보너스 주제별 180세트와 세트별 정확히 세 문제
- 기본 날짜와 보너스 세트마다 난이도별 정확히 한 문제
- 모든 ID와 정규화된 질문 문장의 전역 중복 금지
- 같은 세트 안의 보기 중복 금지
- 출처 URL, 검수일, 콘텐츠 버전, `reviewed` 상태 필수
- 정답 위치 0, 1, 2의 팩별 균형
- manifest 수량과 실제 파일 수량 및 체크섬 일치
- 활성 범위보다 먼저 만료되는 `validThrough` 금지

### 검토가 필요한 품질 경고

- 공백을 제외한 질문이 14자 미만인 경우
- 두 글자 이상인 정답 표현이 정규화된 질문에 그대로 포함되는 경우
- 한 보기의 글자 수가 다른 두 보기 평균의 1.8배 이상이고 8자 이상 차이 나는 경우
- `않은`, `아닌`, `틀린` 같은 부정 조건이 질문에 두 번 이상 등장하는 경우
- 정규화한 글자 3-gram Jaccard 유사도가 0.72 이상인 두 질문
- 동일 `conceptId` 변형의 `setIndex` 간격이 30 미만인 경우

품질 경고가 남은 팩은 `reviewed`가 될 수 없다. 예외가 필요한 경우 콘텐츠 파일에 숨기지 않고 manifest의 검수 기록에 사유를 남긴다.

## 로딩과 오류 처리

- 기본 문제 팩을 불러오지 못하면 홈에서 퀴즈 시작을 막고 재시도 상태를 표시한다.
- 보너스 팩을 불러오지 못하면 선택 화면을 유지하고 광고나 이용권을 소비하지 않는다.
- 팩에 문제 수, 체크섬, 스키마 오류가 있으면 해당 팩을 사용할 수 없는 것으로 처리한다.
- 다른 날짜 또는 다른 주제의 문제로 자동 대체하지 않는다.
- 앱 시작 시 전체 3,780문제를 메모리에 올리지 않는다.
- CI의 실제 `.ait` 빌드를 번들 제한의 최종 판정으로 사용하고, 초기 화면 번들에는 콘텐츠 팩 전체가 포함되지 않았는지 검사한다.

## 분석 이벤트

기존 개인정보 비수집 원칙을 유지한다. 문제 본문, 선택지, 출처 URL은 분석 속성에 넣지 않는다.

- `bonus_topic_daily_complete`: `topic`, `setIndex`, `score`
- `bonus_topic_daily_locked`: `topic`, `reason=daily-limit|exhausted`
- `content_pack_load_failed`: `packType`, `packId`, `reasonCode`

문제 수준 조정은 성숙 코호트에서 기본 평균 점수, 영역별 정답률, 난이도별 정답률을 확인한 뒤 다음 콘텐츠 버전에 반영한다. 클라이언트가 전체 사용자 KPI를 계산하지 않는다.

## 테스트 전략

### 단위 테스트

- JSON 스키마와 새 메타데이터 파싱
- 180일 날짜 계산과 난이도 순환
- 주제별 다음 세트 선택

- 같은 주제의 하루 두 번째 시작 거부
- 다른 주제는 같은 날 시작 가능
- 세트 완료 전 `completedSetIndexes`가 바뀌지 않음
- 중복 명령에서 광고 보상, 이용권, 완료 세트가 한 번만 반영됨
- 세트 소진과 로드 실패에서 권리를 소비하지 않음
- 버전 1과 2 상태의 버전 3 마이그레이션

### 콘텐츠 계약 테스트

- 42개 팩과 manifest의 완전성
- 기본 540개, 보너스 3,240개 수량
- 기본 날짜별 영역과 난이도 균형
- 주제별 세트와 난이도 균형
- 전역 중복, 세트 내부 중복, 정답 위치 균형
- 출처, 검수일, 콘텐츠 버전, 상태, 유효기간
- 의미 유사도 감사 결과에 미해결 경고가 없음

### 통합 및 E2E 테스트

- 오늘 기본 팩만 불러와 세 문제를 완료함
- 보너스 주제를 선택해 다음 미사용 세트를 완료함
- 완료한 주제가 `오늘 완료`로 잠기고 다른 주제는 열림
- 다음 KST 날짜에 같은 주제의 다음 세트가 열림
- 새로고침과 저장 복구 후 일일 제한 및 완료 세트 유지
- 보너스 팩 로드 실패 후 재시도하며 권리를 보존함
- 결과 화면, 공유, 분석이 같은 점수를 사용함
- 콘텐츠 팩이 초기 번들에 모두 eager-load되지 않음

## 구현 및 출시 순서

1. 스키마, manifest, 팩 로더, 검증기와 버전 3 마이그레이션을 먼저 구현한다.
2. 기본 6개 팩 540문제를 제작하고 검수한다.
3. 보너스는 주제별 6개 팩을 독립 배치로 제작하고 검수한다.
4. 전체 42개 팩의 전역 중복과 품질 감사를 수행한다.
5. 통합·E2E·성능·`.ait` 빌드 검증을 통과한다.
6. 모든 팩이 `reviewed`인 단일 릴리스 후보에서만 180일 콘텐츠를 활성화한다.

현재 30일 콘텐츠는 새 파이프라인이 완성될 때까지 기존 경로에서 유지한다. 일부 팩만 준비된 상태로 사용자에게 노출하지 않는다. 3,780문제와 42개 팩이 모두 출시 계약을 통과해야 새 경로를 활성화한다.

## 비목표

- 사용자가 직접 난이도를 선택하는 기능
- 로그인과 교차 기기 진행 동기화
- 서버에서 실시간으로 문제를 내려받는 기능
- 생성형 AI가 앱 실행 중 문제를 만드는 기능
- 무제한 보너스 반복 플레이
- 만료된 콘텐츠를 다른 날짜나 주제로 자동 대체하는 기능

## 완료 기준

- 총 3,780문제가 검수 완료 상태다.
- 기본 180일과 보너스 주제별 180세트가 모두 존재한다.
- 지나치게 쉬운 기존 문항은 승인된 난이도 기준에 맞는 문항으로 교체됐다.
- 같은 기기에서 주제별 하루 1세트와 180세트 무반복이 보장된다.
- 기존 저장 데이터가 손실 없이 버전 3으로 이동한다.
- 콘텐츠 로딩 실패가 광고, 이용권, 진행 데이터를 잘못 소비하지 않는다.
- `npm run verify:quality`, 전체 E2E, 실제 `.ait` 빌드가 통과한다.
- 모든 콘텐츠 팩이 lazy-load되고 manifest와 체크섬이 일치한다.
